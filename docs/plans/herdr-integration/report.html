Locked scope

A user with the integration enabled completes the entire local Agent loop without leaving Termy. Termy finds or starts a trusted local Herdr Service, the sidebar switches to a Herdr view listing local Spaces and Agents with live status, the user creates an Agent, works in its dedicated tab, detaches and reattaches freely, and stops the Agent only through an explicit confirmed action. With the integration disabled, Termy performs no Herdr work at all.

Two words that are not interchangeable. A Termy Workspace is a persisted group of terminal tabs inside Termy. A Herdr Space is a project context managed by Herdr that contains Agents. They are never merged or cross-listed, and the sidebar holds exactly two mutually exclusive views.

S1. One setting, detection only on a fresh configuration
With no saved preference, the integration starts enabled only when a trusted executable is found at an explicit absolute override or a documented install location. An executable reachable only through inherited PATH never triggers this and is never trusted. An explicitly saved preference wins on later launches. While disabled, no detection, no process start, no connection.
S2. Connect first, start only from a trusted absolute location
Termy connects to a running Service, and starts one only if none is running, only from the bundled location or operator-configured absolute paths. An untrusted path is never launched and the rejected path is shown. First start is silent and disclosed in the Herdr view.
S3. One sidebar, visible selector, two exclusive views
A visible Workspaces / Herdr selector over one sidebar. The Workspace view is unchanged from upstream.
S4. Herdr first exactly once, then view restore
After the initial auto-enable the Herdr view is shown first exactly once. Later launches restore the last selected view.
S5. Live local catalog
Spaces and Agents with status from exactly starting, running, waiting-for-input, succeeded, failed, updating with no manual refresh. Control ownership and connection loss are separate markers, never status values.
S6. Exact program and argument list
Created from a Space row with an exact program plus argv. No shell-string interpretation exists anywhere. A failed create leaves the form open with the error and adds no row.
S7. One Agent Tab per Agent per window, Native Runtime only
A second open focuses the existing tab, including one parked in an inactive Workspace. On the tmux runtime, opening an Agent shows a Native Runtime requirement and changes nothing.
S8. Close and quit detach only
The Agent keeps running. Reopening reattaches to the same session, shows output accumulated while detached, and continues live.
S9. Stopping is a distinct confirmed action
Only a confirmed Close Agent stops and removes an Agent. Ordinary close never stops. Quitting Termy never stops Agents or the Service, even one Termy started.
S10. Control conflicts are resolved explicitly
A contested Agent opens no tab and offers no input path until the user picks Take Over, Observe, or Cancel. Observe is read-only. Take Over requires its own confirmation and is fully functional in this slice.
S11. Explanatory failure, empty, and reconnect states
Unavailable, untrusted, incompatible, lost connection, and empty each get a clear state. A lost connection preserves the visible catalog and open-tab scrollback and recovers automatically.

Preserved and excluded

Preserved. Ordinary Termy behavior is identical with the integration disabled and enabled. The change is fork-only and purely additive. The Service and its Agents outlive Termy.

Out of scope. Remote Devices and every remote workflow, resource search in the command palette, attention surfacing and notifications, capability version gating, Space and Device management beyond listing, Agent Tabs on tmux, Agent Tab restart survival, and a working-directory input on create.

Architecture

Two new homes plus narrow additive seam edits, so the fork stays cheap to merge with upstream.

Load-bearing decisions

  • Typed writable attachment. Only a writable attach resolution yields a binding, and the binding is the only type exposing the transport's input operation. No binding means no input path exists to call.
  • Observe has no input state to suppress. The Observe attachment type simply lacks the input operation, so read-only is structural rather than policed, and no later code path can restore input without changing the type.
  • Catalog snapshots and events. The Service owns all state. Termy mirrors a whole snapshot plus a revision, with no delta index, following the existing whole-refresh precedent in the tmux runtime. Rendering is a pure function of the mirror.
  • Per-frame drain. The view stays synchronous and drains controller events once per frame at the same call site that already drains tmux events. Disabled is absence: the runtime field is None and no Herdr code path exists.
  • Agent Tab terminal. A third fork-only Terminal variant wrapping the existing PTY-less externally-fed pane terminal. Every exhaustive policy gains an explicit named arm and no catch-all, so the compiler is the sweep detector.
  • Input routing. Keyboard, paste, and mouse for Agent tabs are patched at the two existing pane input seams rather than at their callers, which covers paste and plugin-directed input for free.
  • Persistence. Preferences go through the existing atomic setting writer. Agent panes are excluded from the native workspace snapshot, so an Agent Tab never returns after relaunch as an ordinary dead terminal. The workspace store gets no schema change.

Gates

  1. GM ticket for NF1 to NF3. Blocks P2, P3, P4, P6, and everything downstream. P1 and P5 touch existing files only and are the only work available before it exists.
  2. Protocol contract confirmation before P9. Confirm replay-then-live as one ordered stream per attachment, the mutation idempotency key, and the controller identity string used in Take Over text. Divergence changes only the transport and session modules, which is exactly what the seam is for.
  3. Single implementation owner. One owner holds the diff across all phases. Parallel agents take whole phases in isolated worktrees and never share files. Four behavioral suites (the trust matrix, the controller verbs, the probe spy, and the conflict suite) are authored by a separate seat that never edits production code.

The planning run itself made no commits and took no remote action. That constrained the planning run. A future implementation needs its own commit authorization before any per-phase committed checkpoint can be satisfied.

Verification levels

  1. Unit against the fake transport. Trust rejection matrix, catalog snapshots and revisions, create idempotency, detach versus close verbs, conflict flow, reconnect replay. The fake is the standing double the repository does not otherwise have.
  2. Desktop state tests. Sidebar exclusivity, dedup across active and stashed Workspaces, tmux rejection with zero mutation, quit detaching only, persist-and-restore round trips, and a probe spy proving a disabled startup performs zero probes, launches, and connections.
  3. One gated real-service integration test plus manual passes. It skips when no Herdr binary is present, so it never turns a machine without one red. The manual passes are the end-to-end loop, the Service kill and restart, and the preservation pass on both runtimes with the integration disabled and enabled.

Risks

RiskHandling
Protocol contract facts are unconfirmedThe transport seam and its fake pin the assumed contract. Divergence changes only the transport and session modules. Confirm before P9.
The reused pane terminal carries tmux-specific interception that could misrender Agent outputRetired in P5 before any UI builds on it. Fallback is a construction flag, which is a seam edit and not a new file.
Workspace persistence would restore an Agent pane as an ordinary dead terminalOne exclusion point covers both the active strip and stashed Workspaces. The round-trip test must assert the restore succeeds with layout trees intact, not merely that no terminal stands in.
One-time Herdr-first while the selector is visible but disabledClosed in the repository plan. A dedicated persisted presentation marker remains false when the user changes the sidebar while Herdr is disabled, then flips true only when initial auto-enable forces Herdr.
Agent identity read as a new struct field would need a file outside its phase's named setIt belongs in the glue runtime's identity-to-pane map. Both the input seams and persistence can discriminate on the terminal variant directly.
Merge drift with upstreamSeam edits are single additive branches in a small named set of files. Periodic upstream merges re-verify only those seams.
Install locations are not yet pinnedThey are data constants owned by the trust module. No structure depends on their values.
